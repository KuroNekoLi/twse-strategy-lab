# Local market data

Run the backend with IntelliJ's **Backend Local** configuration (or `SPRING_PROFILES_ACTIVE=local`). The local profile uses port 8081 to match `frontend/public/config.js` and H2. Historical chart requests read persisted OHLCV bars from the database. When a requested symbol/date range has not been verified, the backend fetches the missing range from the configured licensed historical source, validates and stores the bars plus a coverage record, then responds from the database. Repeated requests for a covered range do not call the upstream source. `APP_MARKET_DATA_ON_DEMAND_BACKFILL_ENABLED` controls this behavior and defaults to `true`; the source must have confirmed public-display permission. The configured FinMind adapter is marked `UNVERIFIED` and will not perform public-display backfills. For Fugle, set `APP_MARKET_DATA_HISTORY_SOURCE=fugle` and provide `FUGLE_API_KEY` in the environment. Never put credentials in this file, source control, frontend code, or logs.

The chart API accepts date ranges from 2010 onward, with a maximum request span of five years. It backfills only the requested missing interval, not every historical year for every listed instrument. The old `APP_HISTORICAL_BACKFILL_ENABLED` startup runner is a separate one-time import for one configured symbol; leave it `false` in routine deployments. To close the chart API set `APP_MARKET_HISTORY_ENABLED=false`.

The daily government-open-data importer remains a separate snapshot source for new daily rows. It does not itself recreate pre-installation history. The legacy TWSE monthly client is not selected by default; do not select `APP_MARKET_DATA_PROVIDER=twse-monthly` for public deployments without separate authorization.

At startup, an enabled importer fetches one all-market CSV snapshot asynchronously; weekdays it retries on the configured 18:20 Asia/Taipei schedule. The first chart will only contain the snapshot's available daily bar. The DB grows as daily snapshots are collected; it does not recreate pre-installation history. For deterministic local checks, use the backend's synthetic tests rather than relying on the live CSV's current date.

The Fugle live stream is enabled in the local profile by default, but a personal `FUGLE_API_KEY` is still required. Without it, the endpoint emits a `stream-error` SSE event and makes no vendor connection. Add the key to the **Backend Local** Run Configuration's environment variables in IntelliJ; never put credentials in this file, source control, frontend code, or logs. To disable locally set `APP_LIVE_MARKET_DATA_ENABLED=false`. The server URL defaults to Fugle's documented Taiwan stock v1.0 streaming endpoint and can be overridden with `FUGLE_WS_URL`. Live streaming remains disabled outside the `local` Spring profile.

The backend exposes `GET /api/v1/stocks/{symbol}/live` as SSE. It authenticates to Fugle server-side, subscribes to the `trades` channel for the requested symbol, and emits normalized `status`, `quote`, and `stream-error` events. Quote events identify `source: Fugle`, `freshness: LIVE`, upstream `eventTime`, and server `receivedAt`. The server does not persist vendor messages. Missing configuration, invalid symbols, or disabled streaming emit a terminal `stream-error` event so browser EventSource clients can read a meaningful failure without an HTTP content-negotiation error. This setup is for a private local prototype; provider runtime and any public redistribution/display permission require separate validation.
