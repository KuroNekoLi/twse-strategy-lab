# M3 盤後紙上交易：執行範圍與驗收

依據 `產品規劃.md` 4.4、10、13、14 章。此切片只建立可追溯的本機模擬帳本，不連券商、不建立真實委託、不宣稱真實撮合。

## 範圍決策

- 首版限定單一瀏覽器本機虛擬帳戶，明確顯示此裝置保存、清除資料會遺失，沒有登入／跨裝置同步。
- 先定義不可變事件與可重建投影，現金、持倉、預留款及成交均由事件推導；每筆操作需唯一識別以防重複入帳。
- 盤後日資料模式採指定日收盤價及明確延遲生效規則；不得模擬委託簿、排隊、部分成交、停牌處理、股利或公司行動，除非來源資料與領域規則已驗證。
- 模擬成交的行情衍生資料不落入 M2 設定儲存。授權確認前，交易紀錄只保留必要的使用者指令及帳務數值於本機，匯出／分享及伺服器持久化暫緩。
- 不把 T+2 日曆寫死為實際交割日期；沒有官方交易日曆和規則驗證時只採保守的資金保留模型，並在介面明示與券商差異。

## 驗收條件

| ID | 條件 | 驗證 |
|---|---|---|
| M3-01 | 建立虛擬帳戶、初始資金及唯一事件 ID | 領域單元測試 |
| M3-02 | 買賣及費用以精確十進位帳務計算；現金不足、股數非法、重複請求安全拒絕 | Golden ledger fixtures |
| M3-03 | 持倉、可用／保留現金可由事件重建且重播結果一致 | 投影重建測試 |
| M3-04 | 每種訂單狀態轉移合法；撤單／拒單不產生虛假成交 | 狀態機測試 |
| M3-05 | UI 清楚說明盤後代理價格、延遲、缺少公司行動與非真實成交 | 實際瀏覽器檢查 |
| M3-06 | 獨立 code review 與瀏覽器主要成功／錯誤流程 | 獨立交付 |

未驗證的來源授權、官方交易日曆、公司行動、稅費與券商實務列為 BLOCKED；不能宣稱會計或交易規則等同券商。
