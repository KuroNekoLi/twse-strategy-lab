## 本站介面原則

1. 個股頁先讓人辨認標的、行情日期與價格，再看走勢；收盤資料與即時報價需明確區分。
2. 以本站已支援的「標的 → 走勢 → 回測 → 筆記」建立主導覽；未實作的籌碼、財報或新聞不可做成看似可用的分頁。
3. 圖表工具列與圖表相鄰，所選日期的 OHLCV 清楚可讀，鍵盤與觸控操作保留。
4. 來源、更新時間、授權狀態、價格調整和資料限制可查，但不與價格和圖表爭搶首要視線。
5. 以台灣市場慣用紅漲綠跌；同時保留正負號、文字或形狀，不只靠顏色傳意。紅／綠只在行情語意元件中出現，不拿來當全站品牌按鈕、一般連結或裝飾色；市場模組以中性底色承載漲跌色，避免和主品牌紅競爭。
6. 使用實際資料欄位和可操作入口，不以空白圖、假行情、泛用宣傳文案或裝飾性步驟填版面。
7. 首頁的行情卡要標示交易日期／更新時間、資料來源與延遲狀態；沒有授權或有效資料時，顯示明確空狀態，不用合成走勢冒充市場行情。

## 目前證據與未知

- 這是介面參照與原始碼／瀏覽器檢視，沒有進行使用者訪談、可用性測試或市場規模研究。
- 玩股網首頁與搜尋的額外觀察來自使用者提供截圖；搜尋互動和模組排列是可觀察證據，不代表本站使用者需求已驗證。本站現在首頁和探索頁都能隨輸入查詢標的目錄；首頁提供前 8 筆自動完成，仍可開啟完整探索結果（`frontend/src/app/site-pages.component.ts`）。
- 參考首頁裡的指數、產業、廣度和熱門榜都屬於市場級資料；個股日線 API 不能代表這些 feed。若未來首頁要展示真實市場概覽，需先有合法且覆蓋足夠的資料來源與更新契約。
- 玩股網和 Yahoo 的頁面只用來觀察它們如何組織台股研究資訊；不能據此推論本站使用者一定需要相同功能。
- 目前本站歷史日線的展示授權仍未確認；公開環境不應因此被描述為已有即時行情或完整市場分析。
- 週／月 K 的 API 使用 ISO Mon–Sun 週界與曆月分組，僅聚合查詢範圍內實際收到的日線；因尚無台灣交易日曆與完整性 feed，`coverageStatus` 維持 `UNKNOWN`，不能據此聲稱該期間資料完整。
- 週／月 K 暫時在每次請求時由 provider 日線聚合，沒有新增行情資料表、SSOT 或持久化快取；上游缺資料時無法靠聚合補齊。
- 上表 P0–P3 是團隊整理的後續機會，須依資料權利、工程成本與使用者回饋再排序。
