# 台股研究介面參照與功能機會清單

日期：2026-10-10
狀態：競品功能與介面流程盤點；不是使用者研究，也不是已承諾的產品路線圖。

## 目的

記錄真實台股研究網站中值得參考的資訊架構，並將適合「先理解行情、再檢驗策略」的功能機會留存。這份文件不取代 [`產品規劃.md`](../../產品規劃.md)，也不代表已確認資料授權或供應商合作。

行情持久化、SSOT 與日線衍生週／月 K 的架構提案見 [`MARKET_DATA_STORAGE_SSOT.md`](MARKET_DATA_STORAGE_SSOT.md)。

## 研究方式與範圍

2026-10-10 以 Chrome 實際瀏覽玩股網、CMoney 股市爆料同學會與 Yahoo 奇摩股市的首頁、搜尋、個股與研究分區，並操作圖表週期、標的選取、時間區間等可見控制。玩股網首頁／搜尋的部分介面線索另來自使用者提供的截圖。這是公開介面與功能流程觀察，不是資料品質稽核、使用者研究或投資建議；不複製行情數值、文章、排名或圖像。

頁面會依登入狀態、地區、時間及供應商部署改變。本文只描述本次可見部分，並將延遲、即時與使用者生成內容視為不同產品責任。

## 本輪決策與最小可實作切片

腦力激盪提出交易回放、個股研究工作台、歷史條件篩選、圖表研究標記與社群觀點等方向。獨立挑戰指出：社群需要治理，市場總覽需要全市場資料與權利；自訂圖表預設可能因使用頻率不足增加負擔；交易回放則必須確認成交可以唯一對應標的和日期。

因此本輪選擇先把已存在的回測成交與個股圖表連起來：在單一標的回測中，讓畫面節錄中的成交可開啟相同股票、相同成交日期的歷史圖表；若是多標的組合或日期不在圖表資料中，不提供錯誤導向，清楚顯示限制。其他未節錄成交仍以完整 API 回應為準。這不依賴新行情供應商或資料庫變更，也把「交易為何發生」從原始 JSON 轉成可操作的研究流程。多標的成交在 API 未提供交易所別標的 ID 前不做映射。

此切片的驗收條件：

1. 單一標的回測成交明細以可讀欄位呈現方向、訊號日、成交日、價格／數量及原因，不只顯示 JSON。
2. 畫面節錄中每筆有有效日曆日期的成交都可開啟同一代碼個股頁，並帶入成交日；中間未節錄的成交本輪不提供連結；圖表載入後僅在存在該日 K 棒時選取它。
3. 目標日期早於預設期間時，圖表自動擴大到現有 5 年範圍；若仍沒有相符 K 棒，明示未找到，不能默選最近日期。
4. 多標的回測不提供歧義連結，並說明目前無法把組合成交精確映射到個股圖表。
5. 現有 API 回應與帳務模型不變；頁面可鍵盤操作且在窄螢幕可讀。

這是可逆的前端切片，先以人工任務觀察驗證使用者能否從成交找到其圖表脈絡；點擊或完成率尚未有使用者數據。詳細選項、反例與證據見 [`TRADE_TO_CHART_OPPORTUNITY.md`](TRADE_TO_CHART_OPPORTUNITY.md)。

## 本站介面原則

1. 個股頁先讓人辨認標的、行情日期與價格，再看走勢；收盤資料與即時報價需明確區分。
2. 以本站已支援的「標的 → 走勢 → 回測 → 筆記」建立主導覽；未實作的籌碼、財報或新聞不可做成看似可用的分頁。
3. 圖表工具列與圖表相鄰，所選日期的 OHLCV 清楚可讀，鍵盤與觸控操作保留。
4. 來源、更新時間、授權狀態、價格調整和資料限制可查，但不與價格和圖表爭搶首要視線。
5. 以台灣市場慣用紅漲綠跌；同時保留正負號、文字或形狀，不只靠顏色傳意。紅／綠只在行情語意元件中出現，不拿來當全站品牌按鈕、一般連結或裝飾色；市場模組以中性底色承載漲跌色，避免和主品牌紅競爭。
6. 使用實際資料欄位和可操作入口，不以空白圖、假行情、泛用宣傳文案或裝飾性步驟填版面。
7. 首頁的行情卡要標示交易日期／更新時間、資料來源與延遲狀態；沒有授權或有效資料時，顯示明確空狀態，不用合成走勢冒充市場行情。
